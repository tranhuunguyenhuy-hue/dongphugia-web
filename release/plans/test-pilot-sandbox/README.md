# test-pilot-sandbox (TEST only, DPG-47 03.9 pilot preparation)
Reviewed plan for the existing #511 TEST lane (`m3-admin-api-deploy.yml`, `operation=release-check|release-apply`). `test-` id + `test_only`: runnable only on the TEST project, never Production scope.
- **Step `create-sandbox` (S2, privileged, additive):** schema `dpg_pilot`; roles `dpg_pilot_rw` and `dpg_pilot_ro` (NOLOGIN, NOSUPERUSER, NOBYPASSRLS, NOINHERIT; USAGE on `dpg_pilot` only, no CREATE, no grant option); tables `dpg_pilot.pilot_object` (registry) and `dpg_pilot.pilot_baseline`.
- **Never:** data load (S3), function, default privilege, grant on a pre-existing object, PUBLIC exposure, login, secret, change to any provider hook or existing role.
- **Guard inside the apply transaction:** the precheck is re-evaluated before the first DDL: one synthetic target contract with a non-null positive ceiling, no `dpg_pilot*` schema/role, executor can create roles, size + 2 MiB + 15 MiB reserve <= min(350 MiB, ceiling), no global default ACL for the executor, and every enabled event trigger is the hash-pinned platform `public.rls_auto_enable()` (acts only on CREATE TABLE in schema `public`; this plan creates tables only in `dpg_pilot`).
- **Baseline:** taken before the first DDL of the step, in the same transaction: catalog definitions (relations, columns, views, constraints, indexes, triggers, routines incl. body hash, policies, roles, memberships with PG17 inherit/set options, default ACLs, extensions, event triggers, database ACL, target contract) plus executor-visible row counts of `dpg_*`/`public` tables. **It is a drift detector, not a backup:** updates to existing rows are not detected and no recovery of existing data is implied.
- **Postcheck:** exact ownership/ACL of the two roles and two tables (no CREATE, no grant option, no other grantee), no effective access to the sandbox for any other non-superuser role, no effective data access of the pilot roles to `dpg_*`/`public` relations, and the baseline equals the current catalog.
- **Rollback SQL = S4 draft:** not authorised in S2 and never executed by it; restrictive (explicit drops, schema without CASCADE).
- Disk usage is not observable from SQL; the 70 % disk stop is an Owner-dashboard fact recorded outside this plan.
