## Admin Worker memory (issue #360)
`@prisma/client@5.22.0` wasm: `$disconnect()` does not free the per-client `QueryEngine`; wasm-bindgen only frees it via `FinalizationRegistry`, which V8 does not trigger on WebAssembly memory pressure. A client per request therefore leaked one parsed-schema engine per request (≈1.2 MB/request measured in local workerd) until the isolate hit its memory limit (Cloudflare `exceededResources`/1102). `apps/admin-worker/release-prisma-wasm-engine.ts` frees the engine after `$disconnect()` and `pool.end()`. Re-validate this helper whenever `@prisma/client` is upgraded.

## Hosted stability findings and harness (issue #360, 18 Nov 2026)
- **Workers Free CPU allowance is the binding constraint for Admin.** Cloudflare GraphQL (`workersInvocationsAdaptive`, `isPreview:1`) showed every failed invocation as `exceededResources` with CPU exactly 10 ms while successful Admin pages used p50 95 ms / p99 430 ms and login ~0.5 s (bcrypt cost 12). Raw 100-request probes on Preview: 1 s spacing → 33 OK then 503; 4 s spacing → 88 OK (12×503); Public at 1 s spacing → 0 5xx. A paid plan (CPU limit 30 s) is the only verified remedy; lowering bcrypt cost is not allowed.
- **Admin links must not prefetch** (`src/components/admin/admin-link.tsx`, guarded by a test): 69 of 99 Worker requests in a 3-iteration browser session were prefetches; after the change a login + 7-module flow issues ~10 Worker requests.
- **Prisma engine reuse (option A) is not safe.** A singleton `PrismaClient` with an AsyncLocalStorage-delegating adapter hangs on the first query in workerd, and Prisma's dataloader batches `findUnique` calls across requests onto one request's connection. Per-request engine init costs ~20 ms CPU locally. Keep per-request clients and `releasePrismaWasmEngine()`.
- **Raw SQL must be schema-qualified** (`dpg_app.<table>`): the least-privilege role has no `dpg_app` in its `search_path`; typed Prisma queries are qualified automatically. `src/lib/admin-raw-sql-schema.test.ts` guards the known files.
- **Staging media:** Public reads the CDN host from the real binding `BUNNY_CDN_HOSTNAME`; the Admin CSP `img-src` allows `https://dpg-media-staging.b-cdn.net` only for non-production Admin builds.
- **Publisher gates:** `publish-m3` requires `approved_source_sha` to equal current `main` and a green `quality` push run for that SHA; it refuses while any `v1-worker-release.yml` run is in progress. Do not merge to `main` while a publish is running.
- **Production release gate is flaky.** `v1-worker-release.yml` browser navigation acceptance failed/passed alternately on identical source (runs 35 fail, 36 pass, 39 fail on `d3f846f`; two runs stalled in `npx playwright install` and were cancelled). Do not bypass; see the Owner decision in #360.
- **Hosted UAT harness** (kept out of the repository because it needs a temporary Access service token and synthetic users): paced sequential probe, Playwright login/flow scripts (desktop + iPhone 13), end-to-end Blog/Product CRUD with `<input type=file>` upload, RBAC/logout probe. Always revoke the service token and delete the synthetic users afterwards.
