# V1 CI/CD fast lane

One branch and one PR per issue. Policy: [AGENTS.md](../../AGENTS.md); live state is verified in Cloudflare/GitHub Actions, not in a status file. No parallel deployment paths; Production deploys are serialized and need Owner approval.

1. **Verify** affected source with focused tests, typecheck/build and PR. Required GitHub status: `quality`; documentation-only changes skip expensive application checks, but code, test and workflow changes must pass the actual required checks. The PR gate prints the computed risk lane floor.
2. **After merge (automatic, #505)**: a successful `quality` push on `main` triggers, through an unprivileged gate job that re-checks repository/ref/event/actor/conclusion and that the SHA is still `main` HEAD:
   - `v1-fixed-preview.yml` `publish-m3` to fixed Staging, unless the push is docs/tests-only, `full` lane, superseded, or a UAT lock is held (skipped with the reason in the summary);
   - `m4-production-admin-release.yml` `verify`: packaged Worker against the Production DB read-only, no media test object. It never publishes.
3. **Owner UAT** on Staging for `standard` and above. To hold Staging during UAT, dispatch `publish-m3` with `uat_issue` (the run takes the lock after a successful deploy) or label the issue `staging-uat-lock` and post `STAGING-UAT-LOCK <sha>`. Every Staging publish rechecks newest `main` and the lock right before deploying; an older queued run never overwrites a newer one. **Recovery**: an ambiguous or unreadable lock blocks publishing; the holder or Owner removes the label once the UAT verdict is recorded (never automatic). A manual `publish-m3` that GitHub cancels while pending behind another Staging run is simply dispatched again.
4. **GO and publish** only with `.github/workflows/m4-production-admin-release.yml` `operation=publish` from reviewed `main`. The verify run summary prints the GO template and inputs: `approved_source_sha`, `rollback_version_id` (active version = rollback target) and `go_comment_url` (Owner comment with `GO-PROD <sha>`, `LANE <lane>` for extended/full, `UAT PASS <sha>` or `UAT-WAIVER <sha> <reason>` for standard+, `FLAGS-CHANGE …` only when flags change). Before building and again right before deploying, the lane checks the GO comment (owner, unedited, exact SHA, after a trusted verify PASS, not superseded or revoked, UAT staged for that SHA, lane not lowered, flags change stated exactly), `main` HEAD and the rollback target. Flags come only from `release/production-flags.json`; the deployed version must match it. Supabase function changes use `.github/workflows/m4-production-function-deploy.yml`.
5. **Do not** use `v1-worker-release.yml` (refuses to publish while Production carries the Admin), the M2 `v1-fixed-preview.yml` snapshot lane (recovery/staging only), or any publish of a snapshot/Public-only artifact over the Admin. Do not change DNS or Production settings to make a check pass.
6. **Record** in the assigned issue: the run links (the summary already holds SHA, scope, flags, active/rollback version, deployed version), real live smoke, PASS/FAIL/UNKNOWN. Worker rollback does not restore SQL.

## Production facts and rollback (verify live before relying on them)

- Worker `dongphugia-v1-public-production` serves canonical Public plus the accepted Admin under `/admin-next`; legacy `/admin*` redirects (302). Edge Function `admin-api` runs on Production `bonxyxluzlxfkdetryoo` (`production_writes_allowed = true`, migrations `001`/`002` applied). Public reads through Hyperdrive with the read-only role `dpg_public_catalogue`. Read the active deployment and version from Cloudflare (`/workers/scripts/dongphugia-v1-public-production/deployments`) before every release.
- Rollback order: Worker `wrangler rollback <previous version>` (does not undo SQL) → delete the function → revoke banner grant/policy → `002`/`001` rollbacks; restore from backup only for data loss. Detail: [M4 Admin plan](../deploy/m4-production-admin-plan.md).
- Backup: `.github/workflows/m4-production-backup.yml` daily 19:41 UTC with an encrypted restore rehearsal; see the [backup runbook](m5-backup-recovery-runbook.md). Media/CDN state and rollback ledgers: [CDN normalization](m5-legacy-cdn-normalization-plan.md).

Cloudflare automatic Git Builds were **disabled by the Owner on 2026-11-20** (Owner-reported; not independently verified here, so re-check in the Cloudflare dashboard before relying on it). They are not release authority and must stay off: the only release lane is the reviewed GitHub Actions workflow above. Legacy separate/per-PR Preview workflows are not release authority either; do not dispatch them. Preserve GitHub Environment secrets, actor/target checks and required protection.
